3.2 Correlation Engine

The correlation engine applies multi-stage rule logic to raw events to identify attack patterns that span multiple systems, time windows, and event types. It supports both signature-based rules (detecting known attack patterns) and statistical correlation (detecting behavioral anomalies based on baselines).

1

Event Normalization

Raw logs from all sources are parsed and normalized to a common Elastic Common Schema (ECS) format, enriching each event with user context, asset inventory data, and geolocation.

2

Threat Intelligence Enrichment

Every IP address, domain, file hash, and URL is checked against 15+ threat intelligence feeds in real time. Malicious IOCs are flagged instantly.

3

Rule-Based Correlation

Over 400 built-in correlation rules apply to the normalized event stream. Rules detect multi-step attack chains, lateral movement, privilege escalation, and data exfiltration patterns.

4

AI/ML Anomaly Scoring

The AI engine scores each correlated alert against behavioral baselines. Alerts with anomaly scores above threshold are escalated automatically.

5

Alert Generation & SOAR Trigger

Final alerts are created with full context, evidence trail, affected assets, recommended actions, and MITRE ATT&CK mapping. High-severity alerts trigger SOAR playbooks automatically.

5.2 File Integrity Monitoring (FIM) Module

The FIM module is the most granular layer of endpoint monitoring. It tracks every file system change within configured monitoring scopes — including system binaries, configuration files, web application directories, and sensitive data paths. Changes are cryptographically hashed and compared against known-good baselines.

  • Real-time SHA-256 Hashing: Every file modification triggers immediate hash verification
  • Baseline Management: Approved baselines can be established and any deviation triggers an alert
  • Ransomware Detection: Mass file modification/encryption patterns detected within 5 seconds
  • Compliance Verification: Automated evidence generation for PCI-DSS, HIPAA, and ISO 27001 FIM controls
  • Web Shell Detection: Monitors web directories for unauthorized PHP, ASPX, or JSP file creation

6.2 Policy Engine

The IDS/IPS Policy Engine allows security administrators to define granular detection and prevention rules with full control over sensor selection, severity thresholds, protocol filtering, source/destination IP scoping, and response actions. Policies can be imported from preset libraries or custom-built using the policy editor.

  • Sensor Selection: Route traffic to Suricata, Zeek, or both simultaneously
  • Severity Threshold: Minimum severity to trigger action (Low / Medium / High / Critical)
  • Protocol Filter: Apply rules only to specific protocols (TCP, UDP, HTTP, DNS, SMTP, etc.)
  • Attack Pattern: Regex-based payload matching for custom threat signatures
  • Source/Destination Scoping: Apply policies to specific IP ranges, subnets, or named assets
  • Match Counting: Track how many times each policy has triggered for tuning and auditing

IPS Attack Type Catalog & Detection Mechanisms
Complete reference of all 16+ attack categories detected and blocked by AJNAT IPS with detection logic, scoring, and response actions

The AJNAT IPS engine classifies every detected threat into one of 16+ distinct attack categories. Each category has dedicated pattern libraries (regex-based payload signatures), behavioral scoring rules, confidence weighting, and automated response actions. The threat scoring engine produces a composite risk score from 0–100, which determines severity level (Critical / High / Medium / Low) and triggers the appropriate automated response chain.

🔍 Threat Scoring Formula
Risk Score = Σ(Pattern Match Weight + Behavioral Score + IP Reputation Score + Rate Anomaly Score)
Scores ≥ 80 → Critical  |  Scores 55–79 → High  |  Scores 30–54 → Medium  |  Scores <30 → Low

Chapter 08
WAF — Web Application Firewall
Layer-7 inspection, real-time HTTP/HTTPS threat blocking, and application protection

The AJNAT WAF operates at Layer 7 (Application Layer) to inspect every HTTP and HTTPS request before it reaches backend application servers. Unlike the network-layer IPS which inspects raw packets, the WAF understands the full HTTP protocol context — headers, cookies, request body, URL parameters, and response payloads — enabling highly accurate detection with minimal false positives.

8.1 WAF Detection Architecture

1

Request Interception

Every HTTP/HTTPS request is intercepted by the WAF agent before reaching the backend application. TLS termination allows full inspection of encrypted traffic.

2

Multi-Dimensional Threat Analysis

The WAF engine (classifyThreat function) calculates a composite risk score from: Failed authentication tracking, Request rate analysis, IP reputation lookup, Port activity monitoring, Payload deep inspection using the full attack pattern library.

3

Attack Classification & Scoring

Matched attacks receive the primary ATTACK_TYPE classification, confidence scoring per vector, and a composite threat level (Critical/High/Medium/Low).

4

Action Execution

Based on threat level: Block (Critical/High), Rate-Limit (Medium), Monitor (Low). Events stored in waf_events collection with full payload capture for forensics.

5

Real-Time SOC Reporting

WAF events stream to the SIEM in real time, aggregated by attack type, severity, and source IP for 24-hour statistical analysis available in the SOC dashboard.

Chapter 14
Incident Response Lifecycle
Structured 6-phase incident response from detection through post-incident review

AJNAT SOC implements the industry-standard 6-phase incident response lifecycle aligned with NIST SP 800-61 and ISO/IEC 27035. The platform automates the first 1–3 phases entirely, compressing the time from detection to initial containment from hours to seconds.

1

Detection & Identification

Automated: SIEM correlation, IPS detection, AI anomaly alerts, and threat intel matches trigger incidents. Every alert includes full context, severity, MITRE ATT&CK mapping, and recommended actions.

2

Triage & Classification

Automated: AI engine validates and scores alerts, suppresses false positives, and assigns severity. L1 analysts review Medium-severity alerts; L2/L3 handle High and Critical automatically escalated cases.

3

Containment

Automated (Critical/High): SOAR executes containment playbook — IP blocks, endpoint isolation, credential revocation. Manual: Analyst reviews and approves for medium severity or whitelisted assets.

4

Eradication

Analyst-led with platform support: Remove malware, close attack vectors, patch vulnerabilities, remove malicious accounts, restore clean system state from verified backups.

5

Recovery

Monitored return to production: Gradual unblocking of affected systems under enhanced monitoring. AJNAT watches for signs of re-infection or attacker persistence for 72 hours post-recovery.

6

Post-Incident Review

Platform generates automated incident report with timeline, root cause, MITRE mapping, and lessons learned. New correlation rules and SOAR playbooks are created to prevent recurrence.

17.2 DNS Exfiltration Detection

Beyond sinkholing known malicious domains, AJNAT actively detects attempts to use DNS as a covert data exfiltration channel (DNS tunneling). The detection engine analyzes query patterns for:

  • Unusually long domain labels (>50 characters) containing Base64 or hex-encoded data
  • High query frequency to a single domain not in Alexa Top-1M
  • TXT record queries carrying large payloads
  • Known DNS tunneling tool signatures (dnscat2, iodine, dns2tcp)
  • Statistical entropy analysis of subdomain strings
